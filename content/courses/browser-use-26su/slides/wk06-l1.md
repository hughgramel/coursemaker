# From the registry to your function

---

## Every action is a registered entry

The Tools registry maps action names to handler functions and their Pydantic parameter models.

- Built-in actions (click, type, navigate, done) are pre-registered on the default Tools instance
- Custom actions add new entries to the same registry
- The registry serializes each action's name, description, and parameter schema into the system prompt
- The LLM picks from this list: it never calls Python directly

When you write a custom action, you are adding a new row to the table the LLM reads.

---

## The @tools.action() decorator

Create a Tools instance, decorate a function, pass tools to Agent.

```python
from browser_use import Agent, Tools, ActionResult, ChatOpenAI

tools = Tools()

@tools.action(description='Ask the user a question and return their answer')
async def ask_human(question: str) -> ActionResult:
    answer = input(f'{question} > ')
    return ActionResult(extracted_content=f'Human answered: {answer}')

agent = Agent(task='...', llm=ChatOpenAI(model='gpt-4.1-mini'), tools=tools)
```

The description is what the LLM reads to decide when to call this action.

Source: Browser Use docs: Custom Functions (browser-use team, 2026)

# Typed parameters

---

## Two ways to declare parameters

**Plain function signature:** each parameter becomes a field in the generated schema.

```python
@tools.action(description='Save a note to disk')
def save_note(filename: str, content: str) -> str:
    with open(filename, 'w') as f:
        f.write(content)
    return f'Saved {len(content)} chars to {filename}'
```

**Pydantic param_model:** pass the whole model as one argument. Use this when the schema is complex or you want Field-level descriptions.

```python
from pydantic import BaseModel, Field

class NoteParams(BaseModel):
    filename: str = Field(description='Target file path, e.g. "notes/todo.txt"')
    content: str = Field(description='Text to write')

@tools.action(description='Save a note to disk', param_model=NoteParams)
def save_note(params: NoteParams) -> str:
    ...
```

---

## Injected dependencies

Parameters named after framework objects are filled automatically.

```python
from browser_use import BrowserSession

@tools.action(description='Return the text of all headings on the current page')
async def extract_headings(browser_session: BrowserSession) -> ActionResult:
    page = await browser_session.must_get_current_page()
    elements = await page.get_elements_by_css_selector('h1, h2, h3')
    headings = [await el.get_text() for el in elements]
    text = '\n'.join(headings)
    return ActionResult(extracted_content=text)
```

Available injected names: `browser_session`, `page_extraction_llm`, `file_system`, `available_file_paths`.

**Name matching is exact.** `browser_session: BrowserSession` works; `bs: BrowserSession` does not.

Source: Browser Use docs: Custom Functions (browser-use team, 2026)

# ActionResult

---

## What your action returns

ActionResult is a Pydantic model. The loop reads it after every action.

| Field | Purpose |
|---|---|
| `extracted_content` | Text the agent can see next step |
| `long_term_memory` | Persisted note across many steps |
| `is_done` | True signals the task is complete |
| `success` | Only valid when is_done=True |
| `error` | String description of a failure |

```python
return ActionResult(
    extracted_content='Found 3 matching rows.',
    long_term_memory='Rows: 42, 17, 9'
)
```

Source: browser_use/agent/views.py (browser-use contributors, 2026)

# Restricting an action with allowed_domains

---

## Domain-scoped actions

The @tools.action() decorator accepts an `allowed_domains` list.

```python
@tools.action(
    description='Save the page title to a log file',
    allowed_domains=['news.ycombinator.com', '*.github.com']
)
async def log_page_title(browser_session: BrowserSession) -> ActionResult:
    page = await browser_session.must_get_current_page()
    title = await page.title()
    with open('titles.log', 'a') as f:
        f.write(title + '\n')
    return ActionResult(extracted_content=f'Logged: {title}')
```

On every step, the registry recalculates which actions are visible given the current URL.
If the agent is on a domain not in the list, this action disappears from the LLM's prompt.

Source: Browser Use docs: Custom Functions (browser-use team, 2026)

---

## When to write a custom action

The built-in actions already handle clicking, typing, scrolling, navigating, and extracting.

Write a custom action when:

- You need side effects outside the browser (write a file, call an API, query a database)
- The task requires domain logic the LLM cannot infer from the page alone
- You want to expose a tool only on specific domains to prevent mis-use
- The extraction needs to run specific CSS selectors or structured parsing

Do not write a custom action to replace click or type. The built-in implementations are already aware of element indices and handle edge cases.

---

## Take-aways

1. @tools.action() registers a function on a Tools instance. Pass that instance to Agent(tools=...).
2. Describe the action clearly: the LLM reads the description to decide when to use it.
3. Pydantic param_model gives you Field-level descriptions; plain signatures work for simple cases.
4. ActionResult carries content forward: extracted_content is visible next step; long_term_memory persists longer.
5. allowed_domains scopes an action to specific URLs so the LLM only sees it when relevant.
